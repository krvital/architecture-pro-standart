##### 1. Сайт банка

Сайт банка должен оставаться максимально простым. При сохранении заявки он будет передавать данные напрямую в очередь. Это обеспечивает быструю и надёжную передачу заявок без перегрузки системы кол-центра и сохраняет устойчивость сайта при пиковых нагрузках.

##### 2. Система кол-центра

Принято решение дополнить существующую систему кол-центра, поскольку она уже поддерживает расширение функциональности и в команде банка есть специалисты, способные вносить необходимые изменения. Такой подход позволит:

- использовать уже существующую инфраструктуру и стек технологий;
- избежать необходимости внедрения новой системы для обработки заявок;
- упростить работу сотрудников кол-центра — им не придётся переключаться между разными приложениями, новые функции появятся в привычном интерфейсе.

##### 3. Интернет-банк

Планируется поэтапное развитие интернет-банка. В будущем его фронтенд будет постепенно переписан на **React**, чтобы обеспечить современную архитектуру и гибкость в дальнейшем развитии продукта.

На переходном этапе для сохранения работы существующего функционала будут настроены правила маршрутизации (**routing**) в **nginx**, что позволит плавно разделить старые и новые страницы.

Параллельно начинается формирование команды фронтенд-разработчиков, которая возьмёт на себя поддержку и постепенную миграцию интернет-банка на новую технологическую платформу.



### <a name="_bjrr7veeh80c"></a>**Альтернативы**

##### 1. Система кол-центра

**Альтернатива:** Создать отдельное приложение для операторов, связанное с сайтом и интернет-банком через API.

**Плюсы:**

- Гибкость и независимый релизный цикл.
- Возможность реализовать оптимизированный UX под новый процесс.

**Минусы:**

- Операторам пришлось бы работать в двух интерфейсах.
- Появляется новая точка интеграции и потенциальные проблемы синхронизации данных.
- Увеличивается стоимость поддержки.

Текущая система кол-центра имеет архитектуру, допускающую расширение (микросервисная, Spring Boot + React). В команде есть экспертиза по Java, поэтому проще добавить новый модуль в существующую систему.

##### 2. Интернет-банк

**Альтернатива:** Полная переписка фронтенда интернет-банка на React сразу.

**Плюсы:** Современный стек, единая архитектура.

**Минусы:** Долгий переход, риск нарушения текущего функционала, зависимость от подрядчика по ядру системы.

Выбран постепенный переход с помощью маршрутизации на уровне **nginx**, что позволяет:

- сохранить стабильность существующего функционала;
- развивать новый фронтенд независимо;
- снизить риски и обеспечить плавную миграцию.
